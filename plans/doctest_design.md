# Design: Doctests — Execute documentation examples as tests

## Goal

Run the `@example` directives from NTNT's `// @ntnt` doc blocks as automated tests during `cargo test`, catching examples that have drifted from actual behavior. Modeled after Elixir's doctests.

## Scope

329 examples exist across 17 source files. Of those, ~260 are in pure/deterministic modules suitable for automated testing (string, math, collections, json, csv, url, path, crypto, time, builtins). The rest are in I/O modules (http, fs, postgres, sqlite, env, concurrent, http_server) and will be skipped initially.

## Background

### Current state

Doc blocks already include structured examples with expected output:

```rust
// @example split("a,b,c", ",") => ["a", "b", "c"] ~ "Basic comma-separated split"
// @example split("no-match", ",") => ["no-match"] ~ "No delimiter found"
```

Multi-line examples use `@expected`:

```rust
// @example ~ "POST with JSON body"
//   let opts = map { ... }
//   fetch(opts)
// @expected Ok({status: 201, ...})
```

These are parsed by `build.rs` into `ExampleDoc { code, expected, description }` structs and embedded as JSON in the binary. Currently, examples are documentation only — never executed.

### Why this matters

The blog post "Documentation as a Build Constraint" acknowledges this gap directly:

> "Our examples are documentation only — they're not executed during the test suite. The examples could drift from reality if someone changes a function's behavior without updating the doc block. We validate structure, not semantic accuracy."

Doctests close this gap. Build-time coverage enforcement guarantees every function has documentation. Doctests guarantee the documentation is correct.

## Technical Constraints

Three constraints shape the implementation:

1. **`Value` has no `PartialEq`.** It contains `fn` pointers and `Rc<RefCell<Environment>>`, so `#[derive(PartialEq)]` cannot be used. We need a custom structural comparison.

2. **NTNT's `==` only covers scalars.** The interpreter's `eval_binary_op` handles `==` for Int, Float, String, Bool, but not Array, Map, or EnumValue. We cannot use NTNT's own equality for comparison.

3. **`Value::Display` does not quote strings.** `Value::String("hello").to_string()` produces `hello`, but expected values in doc blocks are `"hello"` (with quotes). String-based comparison between Display output and expected text would fail.

**Solution:** Eval both the example code and the expected value as NTNT expressions, producing two `Value` instances. Compare them with a custom `values_equal()` function that handles all Value variants recursively.

## Approach

### Module imports

Each example references functions from a specific module (e.g., `split` from `std/string`). The interpreter loads all stdlib modules in `new()` via `define_stdlib()`, but they're only accessible after an `import` statement. Some examples also reference module constants (e.g., `PI` from `std/math`) that don't have their own doc entries.

**Solution:** Add `pub fn import_module_all(&mut self, source: &str) -> Result<()>` to `Interpreter`. This defines all exports from a module into the global environment — equivalent to a wildcard import. The test calls this once per module before running its examples.

### Accessing doc data from tests

The doc JSON is generated by `build.rs` and written to `$OUT_DIR/doc_data.json`. Integration tests (in `tests/`) are separate crates and don't have access to `OUT_DIR`.

**Solution:** Add `pub const EMBEDDED_DOC_DATA: &str = include_str!(...)` to `src/lib.rs`. Integration tests import it via `ntnt::EMBEDDED_DOC_DATA`.

## Implementation

### 1. `src/lib.rs` — Expose embedded doc data

```rust
pub const EMBEDDED_DOC_DATA: &str = include_str!(concat!(env!("OUT_DIR"), "/doc_data.json"));
```

### 2. `src/interpreter.rs` — Add `import_module_all()` public method

```rust
/// Import all exports from a stdlib module into the global environment.
/// Used by doctests to set up the environment for example execution.
pub fn import_module_all(&mut self, source: &str) -> Result<()> {
    let module = self.loaded_modules.get(source).cloned().ok_or_else(|| {
        IntentError::RuntimeError(format!("Unknown module: {}", source))
    })?;
    for (name, value) in module {
        self.environment.borrow_mut().define(name, value);
    }
    Ok(())
}
```

### 3. `tests/doctest_tests.rs` — New integration test file (~150-200 lines)

#### Data structures

Minimal deserialization structs matching the JSON from `build.rs`:

```rust
#[derive(Deserialize)]
struct DocEntry {
    name: String,
    module: Option<String>,
    examples: Vec<ExampleDoc>,
    // other fields ignored via #[serde(default)]
}

#[derive(Deserialize)]
struct ExampleDoc {
    code: String,
    expected: Option<String>,
    description: Option<String>,
}
```

#### `values_equal(a, b) -> bool`

Recursive structural comparison:

```rust
fn values_equal(a: &Value, b: &Value) -> bool {
    match (a, b) {
        (Value::Int(a), Value::Int(b)) => a == b,
        (Value::Float(a), Value::Float(b)) => (a - b).abs() < 1e-10,
        (Value::String(a), Value::String(b)) => a == b,
        (Value::Bool(a), Value::Bool(b)) => a == b,
        (Value::Unit, Value::Unit) => true,
        (Value::Array(a), Value::Array(b)) => {
            a.len() == b.len()
                && a.iter().zip(b).all(|(x, y)| values_equal(x, y))
        }
        (Value::Map(a), Value::Map(b)) => {
            a.len() == b.len()
                && a.iter().all(|(k, v)| {
                    b.get(k).map_or(false, |bv| values_equal(v, bv))
                })
        }
        (
            Value::EnumValue { enum_name: en1, variant: v1, values: vals1 },
            Value::EnumValue { enum_name: en2, variant: v2, values: vals2 },
        ) => {
            en1 == en2
                && v1 == v2
                && vals1.len() == vals2.len()
                && vals1.iter().zip(vals2).all(|(x, y)| values_equal(x, y))
        }
        // Cross-type numeric comparison
        (Value::Int(a), Value::Float(b)) => (*a as f64 - b).abs() < 1e-10,
        (Value::Float(a), Value::Int(b)) => (a - *b as f64).abs() < 1e-10,
        _ => false,
    }
}
```

#### `eval_ntnt(code) -> Result<Value>`

```rust
fn eval_ntnt(code: &str) -> Result<Value, String> {
    let lexer = Lexer::new(code);
    let tokens: Vec<_> = lexer.collect();
    let mut parser = Parser::new(tokens);
    let ast = parser.parse().map_err(|e| e.to_string())?;
    let mut interpreter = Interpreter::new();
    interpreter.eval(&ast).map_err(|e| e.to_string())
}
```

#### Skip rules

**Module skip list** (require external resources):
- `std/http`, `std/http/server`, `std/fs`, `std/env`
- `std/postgres`, `std/sqlite`, `std/concurrent`

**Per-example skip conditions:**
- No `expected` value (demonstration only)
- Expected contains `...` (placeholder, not real NTNT)
- Expected fails to parse as NTNT (skip with warning, don't fail the test)

#### Test function

```rust
#[test]
fn test_stdlib_doctests() {
    let docs: Vec<DocEntry> = serde_json::from_str(ntnt::EMBEDDED_DOC_DATA).unwrap();

    let skip_modules = ["std/http", "std/http/server", "std/fs",
                        "std/env", "std/postgres", "std/sqlite", "std/concurrent"];

    let mut passed = 0;
    let mut failed = 0;
    let mut skipped = 0;
    let mut failures: Vec<String> = Vec::new();

    // Group by module, create one interpreter per module
    let mut by_module: HashMap<String, Vec<&DocEntry>> = HashMap::new();
    for doc in &docs {
        let module = doc.module.as_deref().unwrap_or("builtins").to_string();
        by_module.entry(module).or_default().push(doc);
    }

    for (module, entries) in &by_module {
        if skip_modules.contains(&module.as_str()) {
            for entry in entries {
                skipped += entry.examples.iter()
                    .filter(|e| e.expected.is_some()).count();
            }
            continue;
        }

        // One interpreter per module with all module exports available
        let mut interpreter = Interpreter::new();
        if module != "builtins" {
            interpreter.import_module_all(module).unwrap();
        }

        for entry in entries {
            for example in &entry.examples {
                let Some(expected_str) = &example.expected else {
                    continue; // No expected value
                };

                if expected_str.contains("...") {
                    skipped += 1;
                    continue;
                }

                // Eval the code
                let actual = match /* eval example.code with interpreter */ {
                    Ok(v) => v,
                    Err(e) => { /* record failure */ continue; }
                };

                // Eval the expected as NTNT expression
                let expected_val = match eval_ntnt(expected_str) {
                    Ok(v) => v,
                    Err(_) => { skipped += 1; continue; }
                };

                if values_equal(&actual, &expected_val) {
                    passed += 1;
                } else {
                    failures.push(format!(
                        "FAILED {}::{}: {} => expected {}, got {}",
                        module, entry.name, example.code, expected_str, actual
                    ));
                    failed += 1;
                }
            }
        }
    }

    println!("\nDoctest results: {} passed, {} failed, {} skipped",
             passed, failed, skipped);
    for f in &failures {
        eprintln!("  {}", f);
    }
    assert_eq!(failed, 0, "{} doctests failed", failed);
}
```

### Interpreter reuse within a module

Each module gets its own `Interpreter` instance (so state doesn't leak between modules), but all examples within a module share that interpreter. This means:
- Module exports are imported once
- Examples can reference each other's definitions if needed (though current examples are all standalone)
- Performance: ~17 interpreter creations, not ~329

For the `eval` call within the shared interpreter, we need to lex/parse the example code and call `interpreter.eval()` directly, rather than using the standalone `eval_ntnt()` helper (which creates a fresh interpreter).

## Expected outcome

When first run, some examples will likely fail — either because the expected values are wrong, or because there are formatting mismatches. Fixing those examples is the whole point. Each fix is a documentation bug that would have otherwise gone undetected.

## Verification

1. `cargo build --profile dev-release` — compiles
2. `cargo test doctest` — runs the doctest test specifically
3. All testable examples pass (fix any that don't)
4. `cargo test` — full test suite still passes
5. Intentionally break a doc example (e.g., change `split("a,b,c", ",") => ["a", "b", "c"]` to `=> ["x"]`), run `cargo test doctest`, confirm it fails, then revert

## Future extensions

- **`ntnt doctest` CLI command**: Let users run doctests manually, outside of `cargo test`
- **User code doctests (Phase 12.5)**: Apply the same pattern to `///` doc comments in `.tnt` files
- **Coverage reporting**: `ntnt docs --test` with per-module pass/fail summary
- **Non-deterministic examples**: Tag examples with `@tag #non-deterministic` to skip or run with tolerance
- **Side-effect examples**: Tag examples requiring setup (files, databases) and run them in isolated environments
