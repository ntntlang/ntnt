# NTNT v0.5.3 Release Notes

v0.5.3 brings native Intent testing without a server, HTTP security hardening, bounded network telemetry, supervised processes, and lossless content/download primitives.

## Release numbering

The previous published release is **v0.5.1**. The v0.5.2 version was used during development but was not tagged or published. **v0.5.3 includes that work**; users upgrade directly from v0.5.1 to v0.5.3. The [v0.5.2 notes](v0.5.2.md) are retained as development history, not a separate downloadable release.

## Highlights

### Native Intent tests without a server

[PR #190](https://github.com/ntntlang/ntnt/pull/190) lets `.intent` files invoke ordinary `.tnt` functions through glossary `call:` / `source:` bindings without requiring a paired HTTP server. Existing result predicates remain available; `native assertions pass` observes assertions made by a selected native test entry.

```bash
ntnt intent lint examples/native_testing/library.intent
ntnt intent check examples/native_testing/library.intent -vv
```

- Executes full modules and relative imports, preserving source attribution and typed structured results.
- Fails non-green for missing selections, unresolved/unsupported actions, empty assertion entries, and caught assertion failures.
- Actual CLI native cases run in supervised child processes with a clean environment, isolated working directory, deadline, and cleanup.
- This milestone is synchronous: native test entries reject task spawning and scheduling, including aliased or caught calls. Synchronous sleep remains supported.
- Ordinary application execution is not subject to that native-test-only restriction.
- Isolation is **not a security sandbox**. Run trusted test code.

A project-wide runner, managed external database/browser fixtures, and the wider DD-078 evidence/governance architecture are not included. The checked-in example demonstrates pure functions and disposable in-memory SQLite.

### HTTP security and binary downloads

[PR #173](https://github.com/ntntlang/ntnt/pull/173), [PR #181](https://github.com/ntntlang/ntnt/pull/181), [PR #184](https://github.com/ntntlang/ntnt/pull/184), and [PR #191](https://github.com/ntntlang/ntnt/pull/191) harden HTTP behavior and extend downloads:

- `fetch` returns redirect responses by default. Explicit request-map `follow_redirects: true` enables NTNT-owned, bounded manual following; `max_redirects` defaults to 5 and accepts 1–10. There is no environment-wide redirect switch.
- Each protected hop is independently validated and DNS-pinned. Non-HTTP(S) targets, userinfo, HTTPS-to-HTTP downgrades, loops, malformed locations, and exhausted hop budgets fail closed.
- Opaque Secret-bearing requests cannot opt into following. Cross-origin hops strip ordinary credentials and custom headers except the documented safe allowlist; body-preserving cross-origin redirects are rejected rather than replaying potentially sensitive data.
- A single timeout budget spans the opted-in chain, with bounded final-body reads. Blocking OS DNS/filesystem calls cannot be preempted; the budget is checked around them. Redirect-cookie sessions and conservative URL-cycle restrictions are documented in the stdlib reference.
- SSRF-protected requests pin the validated DNS addresses for the actual connection and bypass system proxies, preventing connection-time DNS rebinding or proxy-side re-resolution from reopening the boundary.
- `download` supports fetch-compatible request maps, streamed binary writes, bounded/cancellable transfer, and atomic destination promotion.
- Failed, cancelled, truncated, or non-2xx downloads preserve an existing destination before promotion. Promotion is the commit point; an opted-in no-overwrite download whose post-commit temporary-file cleanup fails returns success with an explicit `cleanup_warning` and `temporary_path`, not a false rollback claim.
- Request-map downloads default to no overwrite and no parent-directory creation. Legacy `download(url, path)` retains overwrite, parent creation, and Unix regular-file permission behavior.

### Supervised processes

[PR #184](https://github.com/ntntlang/ntnt/pull/184) adds explicitly imported `std/process` APIs for bounded command execution and supervised long-running child processes.

- Disabled unless `NTNT_PROCESS_ENABLE=1`; `NTNT_PROCESS_ALLOW` can restrict launches to exact canonical executable paths.
- Arguments go directly to the OS; NTNT does not implicitly invoke a shell. Windows `.bat` and `.cmd` targets are rejected.
- Started processes enforce deadlines and capture limits without caller polling. Active commands are cleaned up on runtime shutdown and direct CLI exit paths.
- Unix process groups supervise descendants; captured-pipe workers are cancellable and joined, with platform-specific cleanup on macOS and Windows.
- Completed results are bounded to 64 handles and 64 MiB. Older completed handles can expire.

These are process-supervision primitives, not a shell sandbox or the durable `std/jobs` queue.

### Source-mapped Markdown

[PR #184](https://github.com/ntntlang/ntnt/pull/184) adds `std/markdown.parse_blocks` for semantic Markdown blocks with exact UTF-8 byte ranges and lossless, non-overlapping source slices. Applications can relate parsed content to original manuscript bytes without reconstructing the source from rendered HTML.

### Bounded SNMP GET and numeric WALK

[PR #170](https://github.com/ntntlang/ntnt/pull/170) (GET) and [PR #172](https://github.com/ntntlang/ntnt/pull/172) (WALK) add the explicitly imported `std/netmon` telemetry primitives:

- `snmp_get(target, auth, oids, opts?)` reads one to 64 unique numeric OIDs in request order.
- `snmp_walk(target, auth, oid, opts?)` walks one numeric subtree with strictly advancing SNMPv2c GETNEXT cursors.
- Walk completion distinguishes `out_of_subtree`, `end_of_mib_view`, `no_such_object`, and `no_such_instance`.
- Mandatory look-ahead at `max_results` distinguishes exact completion from truncation. `on_limit: "partial"` applies only to result-limit truncation; protocol, transport, deadline, and byte-budget failures remain errors without prior-row telemetry.
- Requests/responses are capped at 8 KiB each. Walks additionally bound cumulative received bytes to 8 MiB and conservative normalized output to 4 MiB.
- `max_results` is 1–2,048, retries are 0–3, and `(max_results + 1) * (retries + 1)` cannot exceed 4,096. One timeout budget covers the complete operation.
- Correlation, BER framing, ordered OID identity, strict cursor progression, and lossless `Counter64` normalization are validated before returning data.

Live calls require `NTNT_NETMON_ENABLE=1` and an opaque community `Secret`. Private targets additionally require `NTNT_NET_ALLOW_PRIVATE=1` and call-local `allow_private: true`. Targets remain literal IPv4/IPv6 addresses. Importing the module does not send network traffic.

**SNMPv2c is plaintext on the wire.** Opaque secrets and zeroized buffers do not encrypt the protocol. Use trusted management networks, VPNs, or protected tunnels. DNS targets, SNMPv3, GETBULK, SET, traps, and MIB-symbol resolution are not included; the MIB-catalog work remains design-only.

## Upgrade guidance from v0.5.1

1. **Audit redirect-dependent requests.** Prefer the final canonical HTTPS endpoint, or explicitly pass `map { "follow_redirects": true, "max_redirects": 5 }` to opt into bounded, per-hop-validated following. Existing callers remain non-following by default: a bootstrap URL such as `https://rdap.org/autnum/15169` returns HTTP 302 without the option. Opt-in does not permit SSRF-policy bypass, unsafe body replay, or opaque-secret forwarding.
2. **Check proxy-dependent deployments.** SSRF-protected HTTP requests connect directly rather than using system proxies. Verify outbound connectivity before upgrading applications that require a proxy.
3. **Preserve file and text expectations.** Legacy two-string downloads retain their file behavior; new request-map calls use safer defaults. Opted-in fetch bodies use bounded UTF-8 decoding with replacement rather than response charset decoding; opted-in fetch/download bodies use `NTNT_MAX_RESPONSE_SIZE` (50 MiB by default).
4. **Keep optional capabilities opt-in.** Existing applications do not need to enable process execution or SNMP just to upgrade. Avoid granting broad process access merely to run tests.
5. **Test the exact candidate with your application.** Native tests are synchronous and are not a replacement for realistic HTTP, storage, worker, and deployment checks. `ntnt test` / `intent check` retain the strict-by-default verification posture from prior releases.

## Known limitations retained in this release

These issues remain open; this release does not claim to fix them:

- [#182](https://github.com/ntntlang/ntnt/issues/182) — completed concurrent-task retention can grow memory under repeated non-empty `parallel()` workloads.
- [#183](https://github.com/ntntlang/ntnt/issues/183) — unreachable closure/environment cycles and incomplete scope restoration need dedicated runtime work. Long-running closure-heavy workers require particular care.
- [#175](https://github.com/ntntlang/ntnt/issues/175) — binding a string directly as PostgreSQL `timestamptz` can fail; explicitly infer text before casting, for example `$1::text::timestamptz`.
- [#187](https://github.com/ntntlang/ntnt/issues/187) — multiple worker processes using the same working-directory control socket can collide. Do not assume independent worker control endpoints in that deployment shape.

The project-wide verification runner, obligation-truth model, formatter, and broader correctness roadmap remain separate follow-up work. Their open issues/design documents are not shipped APIs.
