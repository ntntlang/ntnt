# NTNT v0.5.2 Release Notes

v0.5.2 adds a batteries-included passwordless email coordinator on top of the low-level magic-link primitives introduced in v0.5.1. Applications keep ownership of delivery and authorization policy while `std/auth` owns the generic security ceremony.

## Highlights

- **Coordinated magic-link flow**
  - `magic_link_flow(req, options)` serves the request page, a generic response with best-effort padding, fragment-clearing confirmation page, token consumption, authorization callback, and request-aware session completion.
  - The same helper mounts on the configured request and consume routes; application code supplies only eligibility, delivery, and post-consume authorization callbacks.
  - `issue_magic_link(...)` and `consume_magic_link(...)` remain available unchanged for applications that need the low-level token lifecycle.

- **Safe browser and origin handling**
  - Bearer tokens remain in URL fragments until explicit confirmation and are never placed in callback query strings or paths.
  - Callback links use an explicit trusted `base_url` or `SITE_URL`, never request `Host` or forwarded protocol headers.
  - Default HTML responses are non-cacheable and include restrictive content-security, referrer, framing, MIME-sniffing, and permissions headers.

- **Durable abuse controls**
  - Client limits run before eligibility checks; eligible-identity limits run before issuance.
  - Counters are atomic across memory, SQLite, PostgreSQL, and Redis/Valkey and store only HMAC-scoped keys, counts, and expirations.
  - PostgreSQL and Redis contract tests now run in the required auth-backend CI job.

- **Authorization and session boundary**
  - Tokens are consumed before application authorization, and rejection never restores them.
  - The coordinator forces provider, subject ID, and canonical email from the consumed local identity. Authorization callbacks may add claims, data, display name, and picture but cannot replace the authenticated principal.
  - Session and cookie lifetimes honor per-flow overrides while remaining capped by the configured absolute session maximum.

- **Delivery failure safety**
  - Failed delivery discards the exact token issued for that callback without revoking a newer concurrently issued token.
  - Delivery callbacks receive a `budget_hint_seconds` budget that their provider call must enforce. Response padding remains best-effort and is not a preemptive callback timeout.

## Upgrade notes

- Existing v0.5.1 magic-link integrations continue to work unchanged.
- Applications adopting `magic_link_flow(...)` must provide a trusted link origin and the three policy callbacks. The default client budget uses the immutable socket-peer address. Forwarded client-IP headers remain opt-in and should only be named when ingress strips spoofed values.
