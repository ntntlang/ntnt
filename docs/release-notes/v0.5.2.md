# NTNT v0.5.2 Release Notes

v0.5.2 introduces the first deliberately narrow `std/netmon` slice: a gated, bounded SNMPv2c multi-OID GET primitive for infrastructure telemetry. The module is bundled but remains explicitly imported and does nothing unless an application calls it with `NTNT_NETMON_ENABLE=1`.

## Highlights

### Bounded SNMPv2c GET

- `snmp_get(target, auth, oids, opts?)` reads one to 64 unique numeric OIDs in request order.
- Slice 1 accepts literal IPv4 and IPv6 targets only; hostname lookup, WALK/BULK WALK, traps, MIB-name resolution, and SNMPv3 remain deferred.
- Requests and responses are capped at 8 KiB, retries are capped at three additional attempts, and one monotonic timeout budget covers request encoding, UDP send/receive, and all attempts.

### Strict protocol boundary

- An ntnt-owned BER codec completely validates the SNMP message, response PDU, version, community, randomized request ID, agent status, varbind count, and ordered OID identity before returning telemetry.
- Malformed lengths, trailing data, partial varbinds, oversized datagrams, substituted OIDs, and responses received after the deadline fail closed.
- `Counter64` values remain lossless through `u64::MAX`; binary octets use explicit hexadecimal encoding.

### Credential and target safety

- The SNMP community must be an opaque `Secret`; plaintext strings are rejected.
- Credential-bearing request and response buffers are zeroized. Encoded request storage is discarded immediately after the socket send.
- Every protocol call requires `NTNT_NETMON_ENABLE=1`.
- Private and loopback targets additionally require `NTNT_NET_ALLOW_PRIVATE=1` and per-call `allow_private: true`.
- Metadata, multicast, broadcast, unspecified, documentation, and other prohibited targets remain blocked by the shared `std/net` policy.

## Deployment notes

SNMPv2c sends its community and payload without encryption or cryptographic integrity. Opaque `Secret` handling protects application/runtime memory and diagnostics; it does not make the wire protocol confidential. Deploy this primitive only on trusted management networks or through a protected tunnel.

Example process configuration for a private device:

```bash
export NTNT_NETMON_ENABLE=1
export NTNT_NET_ALLOW_PRIVATE=1
```

The call must also pass `allow_private: true`.

## Compatibility

`std/netmon` is opt-in and not part of the prelude. Existing applications that do not import and invoke the module retain their previous runtime behavior and require no new environment variables.
